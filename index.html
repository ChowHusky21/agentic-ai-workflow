Agentic AI Workflow Ledger

I use AI agents the way a security team should use any privileged automation: least privilege, separation of duties, a human approval gate before anything changes, and an audit trail that records the agent's mistakes as carefully as its output.

This ledger covers twenty days of real work on my own projects: my public professional profiles, two open portfolio repositories, a job search, coursework and a home security lab. It is written for hiring managers and practitioners who want to see how I think about control, not just what the tools can do.

Method

Five stages, with reading kept apart from changing

Each stage is a separate prompt template with its own permissions. An audit can't edit anything, a draft can't publish, and an apply step can only carry out what was approved.

1 · Audit, read-only

Observe

Scores live profiles and repositories. Anything unreachable is flagged and skipped, never guessed.

2 · Draft, no live access

Propose

Writes proposed changes to a dated, versioned document for review.

3 · Human gate

Approve

I approve each item explicitly. Approval never carries over to the next item or the next run.

4 · Apply, one at a time

Change

Only the approved change, one platform at a time, so a mistake stays contained.

5 · Verify and log

Confirm

Re-reads the live result, such as a commit hash or exact published text, then files a dated log.

The loop closes through the templates. When a run exposes a gap, the fix becomes a rule in the next template version, so later runs don't depend on anyone remembering the lesson. The main audit template reached version 20 in this period.

Verification

False alarms: when a check says "no," confirm it before acting

An audit that reports something as missing, empty, broken or mismatched when it is fine is raising a false positive. Over twenty days the audits raised 12 of them. Every one was caught before it led to an unneeded change on a live profile, as far as the records show. Most were caught when I challenged the finding.

Scope

Where the agent helps, and where I keep it out

The agent does

  • Read-only audits of public pages and repositories
  • Research, with every source logged and dated
  • Drafts: profile copy, documentation, cover letters and plans
  • Approved, individually verified commits to my own repositories
  • Record-keeping: versioning, archiving and run logs

The agent doesn't

  • Act without explicit approval for that specific item
  • Submit job applications; I review and submit each by hand
  • Publish social media posts; it drafts, I post (since Oct 1, 2026)
  • Enter passwords or handle credentials
  • Touch protected health information or client systems
  • Delete records; since Sep 26, superseded versions are archived
